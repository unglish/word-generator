# Runtime observer contract before corpus outcomes

The new observer accepts exact v1 controls and active v2 words as distinct
contracts. Frozen v1 observers are unchanged and must reject an active word;
v2 is never disguised as a v1 trace. Actual six-domain v2 labels are checked
against recorded pipeline stages and lexical/surface words. Missing phases are
reported as unavailable, without synthesized labels or zero-defect credit.

For v2, independently reconstruct shared quantity/operational weight from the
actual before-primary segments and pinned policy. Reconstruct the complete
explicit-secondary and left-to-right rhythmic proposal from its recorded draws,
including all skips, gate failures, zero weights and endpoint gates. Verify the
separate proposal assignment namespace, both proposal snapshots and actual K.
Then use the accepted public pure-law API as a same-engine integration replay
of every component/backward sample draw, checking the full recorded sample and
its selected pattern. This transfer check is not a new independent proof of the
law; the separate literal-history mechanism verifier supplies that independence.

Reconstruct applied assignments from one actual primary and one ascending
application of each sampled secondary. Replay prefix/suffix stress using the
actual Q06 resolved forms, including zero-syllable flattening and allomorph
arrays whose lengths differ from declared counts. Each effect must map to the
unique configured planned form and reference its actual word-coordinate event
chain. Verify every overwrite's previous origin, all snapshot event cursors,
root-to-word shift and final lexical/surface correspondence. Primary draws are
checked for supported value/count and traced assignment, without claiming an
independent reevaluation of the inherited primary-strategy model.

For each distinct active returned input/K, query every same-primary pattern of
that K (including exact zero-support patterns) up to nine root syllables. Record
prior/tilted masses, normalization, conditional adjacency expectations and
support-cost variation. An independent Python verifier uses the unchanged
literal-history Fraction oracle to reconstruct prior probabilities, then Decimal
exponentiation at the exact binary64 lambda value for tilted expectations.
It checks all context counts and every observed selected/proposed pattern's
support. Repeated histories are summed; no selected-index pairing with control
is used. Expectations describe each returned input, not an unbiased sample of
pre-rejection attempts. Realized aggregate proposal/application differences and
final assembled stress are separate observations.

The existing registered tolerances remain unchanged. Exact structure, support,
coordinates and counts must match; probability absolute 1e-12, relative 1e-10
when the reference is at least 1e-12, finite-log absolute 2e-10, normalization
absolute 2e-12. Roots outside the declared corpus bound, unsupported schemas,
unknown config/quantity policy, or incomplete archives fail analysis rather
than being omitted. Unknown nuclear quantity remains explicitly unknown.

Before full corpus analysis, public-API observer fixtures cover K0, fixed-K
adjacent disyllables, variable-cost support, both neighbor policies, zero
candidate weights, gate endpoints, nine-syllable roots, resolved/zero-length
morphology, trace detachment and reduced surfaces. Forged fixtures alter phase
labels, origins/cursors, proposal versus applied flags, an otherwise valid
sample uniform/branch, K, component IDs, omitted iterations/events, weight and
configuration evidence, and actual affix coordinates. The independent history
verifier has synthetic support/normalization/denominator corruptions. No test
frequency or candidate corpus outcome is used to choose these criteria.

The independent raw counter verifies the externally supplied freeze, raw manifest
and Node-analysis report byte hashes, every manifest-listed compressed artifact,
the exact scheduled shard set, embedded source bytes, configuration/engine
binding, and each pinned current source before and after. Exact source-path-set
discovery and full raw RNG-boundary accounting remain in the separate Node
capture reader; the Python counter does not claim to reconstruct unrecorded RNG
values or replay sampler/affix event semantics. It independently recounts every
active report group and its input/K context from saved records, and proves every
context's declared-law masses with the literal-history oracle. Its context-key
serialization is scoped to the registered configuration's integer settings and
binary64 ln(2), covered by a cross-language hand-input fixture; it is not a
universal JavaScript-number serializer for arbitrary custom configurations.

The conditional expectation check is a statement about the declared continuous
law. The public sampler replay is the reviewed binary64 implementation on the
pinned Node engine; its finite-grid distinctions and RNG-resolution limitations
remain those of #334. Neither the returned empirical proposal/application
counts nor the mathematical conditional inequality is presented as a new proof
of exact machine-level probabilities or an unbiased corpus-level benefit.
