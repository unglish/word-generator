## Recommendation

Migrate **only `scripts/generate-bigram-table.ts`** into an explicit, fail-closed manual builder for a separately versioned phone-transition reference. Keep the script as the user entrypoint; implement its typed aggregation and artifact contract in `evaluation/corpus/`. Reuse the shared CMU parser/selector and the published joint reference. Do not write a second character builder: `evaluation/corpus/joint-cli.ts:6` already rebuilds all three character tables, and `joint.ts:50` is their shared counter.

This is a genuinely missing aggregate. The joint reference has phone marginals, stress sequences and #304 onset/rime counts (`joint.ts:32`), but not consecutive phone-pair counts. Adjacent pairs cannot be reconstructed from those marginals; the new builder must traverse the exact same selected source entries. This is not a wrapper that merely republishes existing marginal fields.

The independent scope is reference construction and safer manual publication, **not scorer adoption**. Keep `src/phonotactic/arpabet-bigrams.ts`, `score.ts`, `english-baseline.json`, every gate/threshold, the #304 model/scores, demo reference files and frozen evaluator archives byte-identical. A new artifact does not demonstrate better generated words. A consumer adoption PR must compare old/new scores on the same frozen outputs before choosing any new target.

## Proposed API and artifact contract

Keep the existing entrypoint, but require `--source PINNED_CMU --policy cmu-ascii-first-v1 --units integer-phone-transition-occurrences --out NEW_REFERENCE.json`. Missing/unknown options fail; help works without source. No download/default output, no overwrite/legacy export option, no TypeScript runtime-module writer. Resolve repo resources relative to the script and user paths against cwd.

1. Add a small pure typed counter in `evaluation/corpus/phone-transitions.ts`, consuming `readonly SelectedCmuEntry[]` from the existing parser. Do not add a regex parser or another selector. Produce native-token pairs first, retaining AH0/1/2 and ER0/1/2, and an explicitly named `cmu-arpabet-base-v1` projection. Project each endpoint through its parsed base; `#` is a boundary marker, never a phone. Both views include exactly one start and one end boundary per nonempty selected entry, no cross-word pairs and no `# -> #`. Record the stress-merging loss; make no IPA/dialect conversion.
2. New `cmu-phone-transition-reference-artifact-v1` carries source/parser/population identity, selected-entry digest, units, boundary/traversal definition, native and projected nested pair counts, per-first-token totals, total transition count and observed vocabulary. These are counts only: no smoothing, probabilities, scored English distribution or replacement thresholds.
3. Parent identity is the existing #325 joint artifact/reference, not a newly trained corpus. Validate the full parent using `validateJointEnvelope` with trusted checkout source snapshots, verify the compressed published bytes, rebuild `buildJointReference(raw)` and require complete equality. Then derive pairs from `selectCompatibleCmu(parseCmuRecords(raw))` and require the same entry digest. Repeated parsing is acceptable; avoid mutating frozen shared files merely to save that small offline cost.
4. Reuse `jsonDigest`, `PHONE_PROJECTIONS`, `SourceFile`, the shared parser/selector and joint validation. Preserve the frozen #325 implementation closure. A narrow new writer may follow #327/#329 integrity conventions; do not make phone adjacency depend on a marginal-phoneme CLI just to reuse its name-specific writer. No generic format registry or redundant character wrapper is needed. If common writer I/O is extracted, treat the provenance change as its own explicit change with new source identities; it is not necessary for this slice.
5. Validation must compare the **complete expected pair table reconstructed from trusted raw bytes**, not only totals/marginals or self-rehashed embedded code. A 2×2 swap can preserve every marginal while changing adjacency. A caller-facing validator should therefore take trusted reconstructed transition data/parent/sources, or a separately pinned independently verified expected table digest, in addition to the untrusted envelope. Embedded sources alone do not authenticate an artifact.
6. Preserve CMU license and exact parent identities by reference/compact embedded metadata; do not duplicate the raw dictionary or full joint reference. Snapshot the new counter, writer, entrypoint and frozen dependencies/lock. Before exclusive creation, recheck raw bytes, parent bytes and source snapshots. Use fresh output with existing parent directory; reject existing files/symlinks and protected destinations (including aliases and missing targets inside `src`, `data/cmu`, demo, frozen experiment packages, and implementation files). Keep the source input itself protected.

This intentionally changes the manual command’s publication contract; normal generation, scoring and verification continue using old inputs. Update `docs/phonotactic-scoring.md:70` so it stops advertising this command as an in-place regeneration sequence. State the separate score-baseline command remains a legacy unresolved workflow until its own PR, rather than claiming Q15 regeneration is complete.

## Validation and acceptance before publication

Freeze the small counter/schema/protocol before acceptance runs. The design audit below is exploratory; it is not an independent validation result.

- Independently parse the pinned raw bytes in Python and reconstruct both complete pair tables, native-to-base projection, selected-entry digest, exclusion totals and parent marginals. Check **every bin**, row total and vocabulary member. Pair support counts such as 1,339 are descriptive, not optimized targets.
- Conservation: total pairs = phone events + entries; start and end sums each = entries; internal pairs = phone events − entries. Every nonboundary token’s outgoing row total and incoming column total each equal the corresponding native/base phone marginal in the verified joint parent. No absent token silently vanishes. Do not use these marginal invariants as a substitute for full-bin reconstruction.
- Meaningful pure fixtures: a one-phone vowel entry, repeated adjacent token, AH0 versus AH1 versus AH2 and ER variants, multiple word entries with no cross-word pair, custom ordering, and detached returned maps. Shared-selector integration fixtures cover lowercase source, alternatives, invalid/unknown phones (whole entry rejected), comments, apostrophes/Unicode, vowelless records and first-valid duplicates without reimplementing their policy.
- Forgery fixtures: wrong/missing/extra bins; noninteger/negative/percentage counts; wrong boundary convention; altered projection/units/population; a margin-preserving 2×2 pair swap with recomputed envelope digest; changed embedded sources with recomputed digest; wrong parent/raw checksum; truncated/invalid UTF-8 source; extra fields. Reject before publication.
- Real CLI checks from repository cwd and an unrelated cwd, paths with spaces, both tsx entrypoints, required/unknown options, missing input, existing output/symlink/protected aliases, and deterministic identical bytes at two fresh paths. Confirm no partial file on any rejected input.
- Exact before/after checksums for all `src`, `data/cmu`, demo references, #304 model/scores and every existing experiment file. Retain old frozen closures; do not recapture the original generator baseline. The candidate runtime source closure must equal the parent closure. No generator/RNG/performance claim follows from this offline tooling change, and a new 200k generator capture would add no evidence here.
- Run focused corpus fixtures, `npm run test:review`, strict corpus/review TypeScript and explicit lint for new corpus/script files (the default lint glob does not cover all of them). Verify existing scorer fixture outputs are identical; no threshold update or changed expected quality result.
- Package compact new artifact, raw-independent reconstruction report, CLI checks, checksum comparison, source closure and reproduction instructions in a new experiment directory. Any eventual scorer adoption uses this artifact as an explicit dependency and gets a separate unchanged-output score-sensitivity study, with old/new reference identity recorded. No human quality claim.
