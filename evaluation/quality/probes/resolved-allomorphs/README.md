# Resolved allomorph preservation: preregistration

Registered 2026-09-26 before changing the allomorph runtime. Compare the immutable
original 200,000-word development archive with a candidate generated by the same
protocol. Never regenerate the original or inspect validation seeds for tuning.
No affix inventory, weight, cleanup policy, pronunciation order, or quality gate
is to change. This corrects the handoff between attachment and written cleanup.

Candidate tracing will distinguish planned forms, selected forms and their
original allomorph indices, the actual boundary phoneme used during selection,
assembled written parts after root/boundary transforms, and emitted parts after
cleanup. These must be independent snapshots, not references to mutable config or
surface phonemes. Existing prefix/suffix labels remain planned forms.

Measure by profile, replicate, and actual prefix/suffix/both morphology:

- Explicit resolution coverage and counts by affix, original variant index, and
  boundary phoneme. Missing historical fields are unknown, never successful
  preservation or absence of allomorphy.
- Candidate part assembly and output agreement; resolved prefix/suffix text must
  enter the corresponding assembled part exactly. Record cleanup changes to each
  part separately, including legitimate or problematic letter loss, rather than
  relabeling the edited text as the originally selected allomorph.
- Source-identifiable historical `in`→`im` opportunities. The archived English
  inventory has one bilabial-conditioned `im` variant. Identify the root boundary
  from the last recorded root-pipeline snapshot, confirm the configured condition,
  and report final prefix spelling and matching prefix phones. This is a narrow
  source-grounded derivation, not general recovery of missing resolved metadata.
- Preserve all full trace witnesses for bounded examples of selection, cleanup
  change, and mismatch with exact profile, seed and draw coordinates.

The `s`→`es` variant exposes segmentation loss even when reconstruction happens to
retain the same final letters; final `es` alone cannot prove correct historical
part boundaries. Do not infer those missing boundaries from string slicing.
The default inventory contains `im`, not `il` or `ir`; the latter belong only in
explicit custom-configuration tests.

Public-API fixtures cover the default `in`→`im` defect (historically seed 167),
using verified current root contexts, unchanged base forms,
custom longer/shorter prefix and suffix variants (including both), phonological
and syllabic variants, original index preservation under specificity ordering,
actual root boundary transforms, cleanup-induced part changes, trace/no-trace
determinism, snapshot independence, and a continuous development stream.

Use the unchanged frozen diagnostics for side effects, lengths, diversity and
phoneme/trigram distributions. Existing rare-spelling gates remain unchanged.
Equal stream indices are not matched lexical words if changed spelling lengths
alter rejection sampling. Success establishes preserved resolved morphology,
not human preference or an overall wordlikeness improvement.

## Running the probe

```sh
node evaluation/quality/probes/resolved-allomorphs/analyze.mjs BASELINE CANDIDATE OUTPUT
npx vitest run evaluation/quality/probes/resolved-allomorphs/analyze.test.ts
```

Both captures must be complete. The probe verifies manifest/protocol fingerprints,
source and word artifact checksums, scheduled shards, draw coordinates, and frozen
word denominators. It pins its source and registration hashes in the report and
creates the output exclusively; an existing evidence report cannot be overwritten.
